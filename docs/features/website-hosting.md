## Generation

### Landing Page (Pipeline Step 8)

The Website Builder agent generates a complete landing page:

- **Template approach:** Theme JSON + pre-built template structure
- **Tech:** React + Tailwind CSS via CDN (no build step required)
- **Features:** Responsive design, animations, professional styling, CTA sections
- **Validation:** HTML structure, CDN links, tag balance, footer injection

### On-Demand Updates

Users can request website changes via chat (costs 1.5 credits):
- "Update the pricing section"
- "Add a testimonials section"
- "Change the hero color to blue"

## Deployment

### Initial Deploy (Pipeline Steps 11-12)

1. Create GitHub repo in `artha-companies` organization
2. Push HTML to `/website` directory on `main` branch
3. Create Cloudflare Pages project connected to the repo
4. Sync build config (no build command, output dir: `website`)
5. Add custom domain: `{slug}.tryartha.com`

### Subsequent Deploys

When users update their website via dashboard:
1. Updated HTML pushed to GitHub repo
2. Cloudflare Pages auto-deploys from `main` branch

## Serving

### SSR Route

Company websites are served by `src/app/site/[slug]/page.tsx`:

1. Query `pages` table for published page with matching slug
2. Render HTML with injected analytics tracking script
3. Return 404 if project not found or page not published

### Multi-Page Sites

Sub-pages are served by `src/app/site/[slug]/[page]/page.tsx`:
- Checks `pages` table for matching page slug
- Same tracking script injection

## Analytics Tracking

Every company website page includes a lightweight tracking script (injected at render time):

**Script location:** `src/lib/analytics-tracking-script.ts`

**Events tracked:**
- `pageview` — Page load with referrer and screen width
- `pageview_end` — Page exit with engagement duration and scroll depth
- `click` — Button/link clicks with target text and href

**Data flow:** Events batch to `POST /api/site/{slug}/analytics` → stored in `site_analytics` table

See [Analytics](./analytics.md) for full details.

## Website Database

Subscribed projects get an isolated Neon database for dynamic website features:
- User accounts (`site_users` table)
- Custom tables created by AI (products, orders, etc.)
- CRUD operations via Site API

## Dashboard UI

- **Landing page panel** (`src/components/panels/landing-page-panel.tsx`) — Website editor, preview, deploy button
- **Database section** (`src/components/panels/database-section.tsx`) — Table viewer for website DB
